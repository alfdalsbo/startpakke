# Én eier per opplysning

| Opplysning | Kanonisk eier | Andre flater |
| --- | --- | --- |
| Formelt vedtak, dokument og originalt tall | Godkjent originalkilde | Kildepeker, kontrolltid og relevant betydning |
| Konkret saksforståelse | saker/<slug>.md med eventuell dybde | Kort konsekvens og peker |
| Varig fag-/ansvarsområde | areas/<slug>.md | Saksrelasjon med begrunnelse |
| Neste handling, eier og leveransefrist | Valgt oppgavekø | Peker og nødvendig forklaring |
| Valgt uke- eller dagsarbeid | arbeid/UKA.md | Historisk review etterpå |
| Gjeldende porteføljestatus | context/CURRENT.md | Ikke detaljert teknisk logg |
| Prioriteringsbegrunnelse | context/PRIORITERINGER.md | Lenke til eieroppgave |
| Teknisk status og uferdige integrasjoner | context/SYSTEMSTATUS.md | Ingen påstand om usynlig synk |
| Systemvalg som gjelder på tvers | context/BESLUTNINGER.md | Saksvedtak forblir i saken |
| Arbeidsordre og kvittering | oppdrag | Oppgavekøen eier brukerens forpliktelse |

En kopi skal bare ha nødvendig konsekvens og lenke. Endret original kan kreve ny saksforståelse, oppdatert frist og endret ukevalg, men ingen av disse skal bli konkurrerende fasit. En avsluttet sak beholder historisk betydning og kilder. Avslutning betyr ikke at den aldri skal kunne leses igjen.

Når to oppgaveflater brukes, må hvert felt ha valgt eier og objektene være koblet med stabile ID-er. Se [flere oppgaveflater](FLERE-OPPGAVEFLATER.md). Ikke innfør generell toveis synk uten dokumentert konflikt- og feilbehandling.
